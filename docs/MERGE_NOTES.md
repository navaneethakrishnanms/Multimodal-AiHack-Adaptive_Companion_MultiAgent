# Merge notes: two starting points, one project

We were handed two code bases. This file records what we kept from each, what we rejected and why, and where the two sources are credited.

## Source A — the original study-companion repository (base of this project)
Python/FastAPI, TF-IDF retrieval, grounded tutor, quiz generation with a verification pass, Bayesian knowledge tracing, a small single-page UI.
**Kept and extended:** ingestion model (units with `file + page/slide/timestamp`), TF-IDF retriever, the `NOT_COVERED` refusal contract, BKT update math, quiz verification idea.
**Replaced or fixed:** transcript windowing (timestamp labels preceded their first cue by up to 25 s), single global learner (now per-student), `quiz_keys.json` overwritten per quiz (now accumulating, unique ids), dice-roll "simulated students" (now latent-gap students with paired policies), topic-name drift (names are canonicalised), LLM errors surfacing as HTTP 500 (offline fallbacks everywhere), stale evaluation numbers (removed; regenerated by our scripts).
**Removed:** the original demo artifacts and a YouTube upload helper (we never upload; the user does that step by hand). Backed up outside the repo.

## Source B — LearnFlow AI (`multimodel-ai-main`)
React + FastAPI + SQLAlchemy platform with an 8-agent pipeline, JWT auth, a knowledge-map page, a source-viewer modal and an evaluation page.

**Ideas we took (re-implemented in our code, no code copied):**
| LearnFlow idea | Where it lives here |
|---|---|
| "Next Best Action" with an explicit pedagogical reason | `core/recommend.py` — reasons are computed from real mastery, prerequisite blame, forgetting-curve retention and recorded misconceptions, and every action links to sources |
| Misconception tracking per topic with a resolved state | `core/report.py` + `LearnerModel.record_misconception`; generalised to any course (LLM one-liner, fallback to the question's own misconception field) |
| Reject → regenerate verification loop and structural question checks | `core/quiz.py` (duplicate options, broken MCQ keys, near-duplicate stems rejected; mismatching keys dropped) |
| Source Viewer modal with type-specific rendering | Source Viewer panel in `static/index.html` + `/api/source/view` (PDF page image, slide preview, figure, video at timestamp) |
| Knowledge-graph visualiser, mastery bars, evaluation page, study notes page | Cytoscape prerequisite graph, mastery bars, Evaluation tab, flashcards / spoken briefs |
| Guard against raw/garbled document output reaching the tutor | readability checks around ingestion and the offline extractive answer |
| Second course material | `data/sample_courses/os/os_notes.txt` (from its `sample_notes`) used for a second course in the evaluation |
| Docker packaging | `Dockerfile`, `docker-compose.yml` |
| Student accounts | lightweight per-student profiles (no passwords: out of scope for this track) |

**What we deliberately did not take, and why:**
- **Hard-coded misconception rules** (binary search, recursion, sorting, graphs): they only work for one course and would be fabricated knowledge elsewhere.
- **The evaluation runner**: its relevancy and citation scores are constants (`0.92`, `0.95`, a fixed `0.96` "verification pass rate"), not measurements. Our rule is that every reported number comes from a script run.
- **"Fallback" LLM provider** that fakes answers locally: our offline mode is explicitly labelled extractive output from the student's own material.
- **React/Vite build chain and the 8-agent graph**: the Track D deliverable is better served by a no-build UI and direct modules; the agents' responsibilities map onto `ingest`, `retrieve`, `tutor`, `quiz`, `report`, `learner` and `rootcause`.
- **Video ingestion that requires a pre-made `.vtt`**: we transcribe with faster-whisper.
- **Design-skill packs** in `.agents/` (tooling, not product).
